---
title: "pkg.purged"
---

Ensures a package is removed **along with its configuration files**. On Debian this runs `apt-get purge`; on the RedHat family it runs `dnf`/`yum remove` (rpm has no separate purge concept). The purge is performed by shelling out to the package manager CLI, independent of what the package provider's `Remove` does.

**Source**: `pkg/state/modules/pkg_purged.go`

---

## Parameters

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `name` | `string` | No | State ID | Name of the package to purge. |

All states also accept the full set of requisite parameters and Salt-parity state attributes — see [Dependencies & Requisites](/docs/guides/states/dependencies).

---

## Check Behavior

- Converged means **no package record at all**. On Debian the probe is dpkg-status-aware (`dpkg-query -W -f='${db:Status-Status}'`): a removed-but-not-purged package (`rc` state — configuration files remain) still **needs a purge**, which is exactly this state's value over `pkg.removed`. On RedHat the probe is `rpm -q <pkg>` (rpm has no `rc` equivalent).
- Installed or residual (`rc`) state → changes needed; no record → no changes.
- On an unknown package system, Check falls back to the package provider's installed probe; without a provider, Check errors.

---

## Apply Behavior

| OS family | Command |
|---|---|
| Debian/Ubuntu | `apt-get purge -y <pkg>` |
| RedHat (dnf/yum) | `<mgr> remove -y <pkg>` |
| Unknown | Falls back to the package provider's `Remove`; errors if no provider is available. |

The OS family is detected from the `os.family` fact, falling back to the active package provider name.

---

## Revert Behavior

Explicit no-op (same contract as `pkg.removed`): the purged version is never recorded and the purged configuration files cannot be restored, so a reinstall would only guess at the repo's current latest candidate — not the inverse of Apply. Reinstall explicitly with `pkg.installed`.

---

## Examples

### Direct Execution

```bash
zester 'web-01' pkg.purged apache2
```

### State File

```yaml
apache2:
  pkg.purged: []
```

**Purge before installing a replacement:**

```yaml
remove-old-webserver:
  pkg.purged:
    - name: apache2

nginx:
  pkg.installed:
    - require:
      - "pkg.purged:remove-old-webserver"
```

---

## Divergences from Salt

- On the RedHat family, purge is identical to remove (as in Salt — rpm does not track config purging separately).
- Salt's `pkgs` (multi-package) parameter is not supported; use the generic `names` attribute to expand one state per package.
